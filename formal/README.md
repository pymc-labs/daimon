# Formal state-machine coverage

This directory contains finite TLA+ abstractions of selected production state
machines. Source code and executable tests define the behavior; the models make
concurrency assumptions explicit and check the abstractions within stated
bounds. A passing TLC run does not prove the Python, database, adapter, or
upstream service correct.

## Explicit exclusions

This is a risk-ranked inventory, not an exhaustive proof of every feature.
P1/P2 rows are deferred from formal modeling, with their likely interleavings
and existing tests listed above. Lower-priority exclusions are pure decision
functions and view builders; ordinary CRUD without a multi-step lifecycle;
tenant onboarding; credential/vault updates apart from the OAuth flow above;
report-host upload/restart lifecycle (notebook capability is modeled as a
candidate only); and platform SDK internals. Revisit these if new evidence
shows a consequential race or missing invariant.

## Running the current models

Install a JRE, then download the official TLA+ tools v1.7.4 release and verify
its pinned SHA-256 before use:

```sh
mkdir -p "$HOME/.cache/daimon/tla"
curl -fL https://github.com/tlaplus/tlaplus/releases/download/v1.7.4/tla2tools.jar -o "$HOME/.cache/daimon/tla/tla2tools.jar"
printf '%s  %s\n' '936a262061c914694dfd669a543be24573c45d5aa0ff20a8b96b23d01e050e88' "$HOME/.cache/daimon/tla/tla2tools.jar" | sha256sum --check
export TLA2TOOLS_JAR="$HOME/.cache/daimon/tla/tla2tools.jar"
```

From the repository root, follow the sequential run commands in
[`turn/README.md`](turn/README.md), [`scheduler/README.md`](scheduler/README.md),
[`session_preparation/README.md`](session_preparation/README.md),
[`continuation/README.md`](continuation/README.md),
[`adapter_recovery/README.md`](adapter_recovery/README.md),
[`billing/README.md`](billing/README.md), and
[`wizard/README.md`](wizard/README.md). They
document each configuration, bounds, fairness assumptions, checked properties,
and counterexample interpretation. Keep TLC runs sequential in one checkout
when they share a state directory. Add source-linked variable/action mappings
and environment assumptions to each model's README as coverage grows.
