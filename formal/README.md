# Formal state-machine coverage

This directory contains finite TLA+ abstractions of selected production state
machines. Source code and executable tests define the behavior; the models make
concurrency assumptions explicit and check the abstractions within stated
bounds. A passing TLC run does not prove the Python, database, adapter, or
upstream service correct.

## Explicit exclusions

This is a risk-ranked inventory, not an exhaustive proof of every feature.
The remaining boundaries and their likely interleavings are listed above
alongside existing executable tests. Lower-priority exclusions are pure decision
functions and view builders; ordinary CRUD without a multi-step lifecycle;
tenant onboarding; credential/vault updates for URLs other than the one slot modelled in `oauth/`;
report-host reader-turn upload and publish behavior across process restarts
(the single and overlapping publish paths are modeled in [`report_publish/`](report_publish/README.md)); and platform SDK internals. Revisit these if new evidence
shows a consequential race or missing invariant.

## Running the current models

Install a JRE, then download the official TLA+ tools v1.7.4 release and verify
its pinned SHA-256 before use:

```sh
mkdir -p "$HOME/.cache/daimon/tla"
curl -fL https://github.com/tlaplus/tlaplus/releases/download/v1.7.4/tla2tools.jar -o "$HOME/.cache/daimon/tla/tla2tools.jar"
printf '%s  %s\n' '936a262061c914694dfd669a543be24573c45d5aa0ff20a8b96b23d01e050e88' "$HOME/.cache/daimon/tla/tla2tools.jar" | sha256sum --check
export TLA2TOOLS_JAR="$HOME/.cache/daimon/tla/tla2tools.jar"
```

Then check every configuration from the repository root:

```sh
formal/check.sh    # several minutes, depending on host
```

`check.sh` guards every TLC run: it kills TLC when a config's metadir grows
past `TLC_MAX_META_MB` (default 2048) or the run takes longer than
`TLC_TIMEOUT_S` (default 480 s, under the CI job limit). Each config's metadir
is deleted when its run ends. Both variables must be positive whole numbers,
and anything else, such as `2G`, is refused. A killed run fails its row with
the reason (`DISK GUARD …` or `TIMEOUT …`). The guard needs GNU coreutils
(`timeout`, `du`); on macOS, install coreutils first.

`check.sh` runs each row of [`expected.tsv`](expected.tsv) (model directory,
spec, config, expected verdict, distinct-state count, TLC flags) and fails
unless TLC's verdict matches: `clean` for safe configurations,
`violates:<Invariant>` or `violates:<Property>` for the deliberately unsafe
configurations that keep a counterexample reproducible. It also fails unless
the distinct-state count equals the pinned one, and whenever TLC explored 0
states: an emptied `Init` or an over-constrained `Next` still ends in "No error
has been found", so a verdict-only check would pass it as clean. TLC runs with
one worker, so the counts are deterministic; when you change a model on
purpose, copy the new count from the `check.sh` output into `expected.tsv`. The
[`formal-models`](../.github/workflows/formal-models.yml) workflow runs it on
pull requests that touch `formal/` or a source file a model describes. When
you change that code, update the matching model action; when you close a gap,
add a safe configuration expected `clean` and keep the unsafe one expected
`violates:…`. Add every new configuration, with its state count, to
`expected.tsv`.
